# ТЗ: сайт на HTML/CSS/JS с формами через PHP

Универсальное ТЗ. Конкретика сайта (страницы, тексты, формы) сюда не входит: её заказчик описывает Codex отдельным запросом.

## 1. Стек

- HTML, CSS, JS без фреймворков и сборщика.
- Серверный код — только PHP для приёма форм и отправки почты через `mail()`; зависимостей нет.

## 2. Структура репозитория

```text
index.html            страница с формой
css/style.css         стили
js/main.js            отправка формы без перезагрузки
php/send.php          валидация и mail()
.github/workflows/    preview | cleanup | deploy
AGENTS.md             правила работы Codex
TZ.md                 этот файл
README.md             запуск, секреты, переменные
.env.example          список переменных без значений
```

Корень репозитория = корень сайта. Служебные файлы (`.github`, `.git`, `.env`, `*.md`) на хостинг не загружаются.
Имена файлов и папок: латиница, нижний регистр, дефисы.

## 3. Формы

- Единственный обработчик — `php/send.php`. Новые PHP-файлы для форм не создаются: логика чужих обработчиков переносится сюда.
- Форма в HTML, отправка POST на PHP-обработчик.
- Проверка полей обязательна на сервере, JS-проверка — дополнение.
- Получатель письма и данные почты берутся из переменных окружения, не из кода.
- Ответ пользователю: JSON и сообщение об успехе или ошибке на странице.
- Набор полей не зашит в код: обязательные поля, поле с email, поле-ловушка и лимиты заданы в `FORM_CONFIG` вверху `php/send.php`. Под новую форму правится только этот массив.

Текущий контракт формы (эталон шаблона):

| Поле | Обязательное | Назначение |
| --- | --- | --- |
| `name` | нет | имя отправителя |
| `phone` | да | телефон для связи |
| `message` | нет | текст заявки |
| `consent` | да | чекбокс согласия на обработку данных |
| `website` | нет | ловушка для ботов: скрытое поле, у людей всегда пустое |

Список обязательных — это `FORM_CONFIG['required']`, он должен совпадать с колонкой «Обязательное». Меняешь поля — одной задачей обновляешь HTML (`name="..."`), `FORM_CONFIG` и эту таблицу.
- Письмо: тема, поля формы, дата; заголовки без подстановки пользовательских данных (защита от инъекции заголовков).
- Стенд статический (GitHub Pages): PHP на нём нет, форма отключена. Отправку проверяем локально или на проде.

## 4. Секреты и конфигурация

| Что | Где хранится |
| --- | --- |
| Адрес получателя, отправитель, приписка к теме (`MAIL_*`) | Переменные окружения сайта на FastVPS |
| FTP-хост, логин, пароль (только прод) | GitHub Secrets |
| Локальные значения | `.env` (в `.gitignore`), в репозиторий не попадает |

Как PHP на FastVPS читает окружение, проверяется на сервере до написания кода.

## 5. Ветки и деплой

Порядок работы (ветки, PR, стенды, мерж, команды) — в `AGENTS.md`, здесь не дублируется.
Требования к процессу, а не к агенту:

- Прод обновляется только через workflow по `push` в главную ветку репозитория (default branch). Ручная заливка по FTP и прямой push исключены.
- Прод не обновляется со смерженного PR: payload такого события пустой.
- Главная ветка защищена: мерж только после одобрения заказчика.
- Стенд — статика в ветке `gh-pages` на GitHub Pages, папка `pr-<номер>`. Прод — FastVPS по FTP.

## 6. Готовность PR

PR готов, когда: стенд открывается по ссылке, форма отправляется и письмо приходит, ошибки валидации видны пользователю, в описании PR есть что проверять.

## 7. Открытые вопросы

1. Назначение сайта и страницы — описывает заказчик при первом запросе.
2. Версия PHP на FastVPS.
3. Защита от спама: honeypot, капча или ничего.
4. Дизайн: макеты или на усмотрение Codex.
5. Доступ к стенду: публичный или закрытый (`noindex`).

# ТЗ: сайт на HTML/CSS/JS с рендером страниц из данных

Универсальное ТЗ. Конкретика сайта (страницы, тексты, формы) сюда не входит: её заказчик описывает
Codex отдельным запросом. Команды запуска и структура — `README.md`, правила работы агента — `AGENTS.md`.

## 1. Стек

- HTML, CSS, JS без фреймворков и сборщика.
- Серверный код — PHP 8.1+ без зависимостей: роутер, рендер шаблонов, кэш, обработчик формы.
- Хранение страниц — файлы: `data/pages.csv` как источник правды. Базы данных нет.

## 2. Структура репозитория

```text
data/pages.csv        источник правды по страницам
data/pages/           собирается из CSV (в git не хранится)
data/index.json       индекс для сборки (в git не хранится)
index.php             роутер
lib/config.php        пути, адрес сайта, резервные имена
lib/render.php        подстановка полей в шаблон
lib/cache.php         атомарная запись кэша
lib/seo.php           canonical, крошки, JSON-LD, sitemap, robots
templates/            page.html, category.html, 404.html
partials/             header, footer, breadcrumbs, form
scripts/split-data.php  CSV -> JSON, валидация, sitemap.xml, robots.txt
scripts/warmup.php      прогрев кэша (CLI и HTTP по токену)
scripts/build.php       статика для стенда
scripts/check.php       проверка метаданных собранного стенда
cache/                готовый HTML (в git не хранится)
css/style.css         стили
js/main.js            отправка формы без перезагрузки
php/send.php          валидация заявки и mail()
.github/workflows/    preview | cleanup | deploy
AGENTS.md             правила работы Codex
TZ.md                 этот файл
README.md             запуск, секреты, переменные
.env.example          список переменных без значений
```

Корень репозитория = корень сайта. Служебные файлы (`.github`, `.git`, `.env`, `*.md`, сборщики
в `scripts/`) на хостинг не загружаются. Исключение — `scripts/warmup.php`: его вызывает деплой.
Имена файлов и папок: латиница, нижний регистр, дефисы.

## 3. Формы

- Единственный обработчик — `php/send.php`. Новые PHP-файлы для форм не создаются: логика чужих
  обработчиков переносится сюда.
- Разметка формы одна на все шаблоны — `partials/form.html`, отправка POST на `php/send.php`.
- Проверка полей обязательна на сервере, JS-проверка — дополнение.
- Получатель письма и данные почты берутся из переменных окружения, не из кода.
- Ответ пользователю — JSON; сообщение об успехе или ошибке выводится на странице.
- Набор полей не зашит в код: обязательные поля, поле с email, поле-ловушка и лимиты заданы
  в `FORM_CONFIG` вверху `php/send.php`.

Текущий контракт формы (эталон шаблона):

| Поле | Обязательное | Назначение |
| --- | --- | --- |
| `name` | нет | имя отправителя |
| `phone` | да | телефон для связи |
| `message` | нет | текст заявки |
| `consent` | да | чекбокс согласия на обработку данных |
| `website` | нет | ловушка для ботов: скрытое поле, у людей всегда пустое |

Список обязательных — это `FORM_CONFIG['required']`, он должен совпадать с колонкой «Обязательное».
Меняешь поля — одной задачей обновляешь `partials/form.html` (`name="..."`), `FORM_CONFIG` и эту таблицу.

## 4. Страницы и данные

`data/pages.csv` — UTF-8 (BOM допускается), разделитель `,` или `;` (определяется автоматически,
Excel в русской локали пишет `;`). Первая строка — шапка, имена колонок: `a-z`, `0-9`, `_`.

| Колонка | Обязательная | Правило |
| --- | --- | --- |
| `path` | да | адрес без ведущего слэша: `uslugi/remont-kvartir`. Только `a-z`, `0-9`, дефис и `/`; до 4 сегментов. Уникален |
| `type` | да | имя шаблона: должен существовать `templates/<type>.html` |
| `title` | да | уникален по всему файлу |
| `description` | да | дубль — предупреждение сборки, не ошибка |
| `h1` | да | дубль — предупреждение |
| `lastmod` | да | `YYYY-MM-DD`, не в будущем; попадает в `sitemap.xml` |
| `noindex` | нет | `0` или `1`, по умолчанию `0` |
| `body` | нет | сырой HTML страницы |
| прочие | нет | любое имя по тем же правилам; выводится в шаблоне как `{{имя}}` |

Правила, которые проверяет `scripts/split-data.php`:

- `path=home` — главная страница; такая строка обязана быть ровно одна.
- Родитель страницы определяется по `path`, отдельной колонки нет: `uslugi/remont-kvartir` требует
  строку `uslugi`. Иначе сборка падает с подсказкой, какой строки не хватает.
- Первый сегмент не может совпадать с именем в корне сайта (`css`, `js`, `php`, `data`, `lib`,
  `scripts`, `templates`, `partials`, `cache`, `sitemap`, `robots`, `index`).
- Ошибки печатаются все сразу, с файлом, номером строки и полем; код выхода `1`, данные не собираются.
- Поле, которое используется в шаблоне, но отсутствует в шапке CSV — ошибка сборки.
- Сгенерированные файлы каждый раз перезаписываются целиком: удалённая из CSV страница исчезает.

Шаблоны подставляют три конструкции:

| Синтаксис | Что делает |
| --- | --- |
| `{{поле}}` | значение с экранированием `htmlspecialchars` |
| `{{{поле}}}` | сырой HTML; разрешено только для `body`, `_robots`, `_breadcrumbs`, `_related`, `_jsonld` |
| `{{ include имя}}` | вставка `partials/имя.html` (вложенность не больше 3) |

Условий, циклов и хелперов нет: логика считается в PHP и приходит готовой строкой.
Если поле используется в шаблоне, но его нет в данных, страница отвечает `503` и пишет ошибку в лог —
пустая страница с кодом `200` недопустима.

## 5. Адреса, SEO и кэш

- Адрес страницы — `/` для `home`, иначе `/<path>`. Слэш на конце, `/home` и `/index.html`
  редиректятся `301` на канонический адрес.
- `canonical` — абсолютный `https`-адрес без `www`, собирается из `SITE_URL` и `path`.
- `noindex=1` добавляет `<meta name="robots" content="noindex">` и исключает страницу из `sitemap.xml`.
- `sitemap.xml` строится из данных с `lastmod` из CSV (не текущей датой); ссылка на него — в `robots.txt`.
- JSON-LD: `BreadcrumbList` плюс тип страницы по `type` (`WebPage` / `CollectionPage`).
- Крошки строятся из цепочки `path`, блок «Смотрите также» — из дочерних и соседних страниц:
  у каждой страницы есть входящие внутренние ссылки, глубина — до 4 сегментов пути.
- Служебные каталоги (`cache/`, `data/`, `lib/`, `scripts/`, `templates/`, `partials/`) наружу не
  отдаются: `403`. Исключение — `scripts/warmup.php`, доступ к нему закрыт токеном.
- Готовый HTML лежит в `cache/<path>.html` и отдаётся Apache напрямую, без PHP. Поэтому после правки
  шаблона обязателен `php scripts/warmup.php`; запись кэша атомарная (`rename`).
- Ошибка рендера — `503` с записью в лог, несуществующий адрес — `404` с шаблоном `404.html`.

## 6. Ответы `php/send.php`

Всегда JSON, не HTML:

| Код | Когда |
| --- | --- |
| `405` | метод не POST |
| `200` | заявка принята; для бота, пойманного honeypot, — тихий успех без письма |
| `413` | заявка больше `max_body` |
| `422` | ошибки полей в `errors[]` или пустая заявка |
| `500` | нет валидного `MAIL_TO` или `mail()` вернул `false` |

Переменные читаются `getenv()` → `$_ENV` → `$_SERVER`. Тема кодируется `mb_encode_mimeheader`;
пользовательские данные в заголовки не подставляются (только проверенный `Reply-To`).

## 7. Секреты и конфигурация

| Что | Где хранится |
| --- | --- |
| `MAIL_TO`, `MAIL_FROM`, `MAIL_SUBJECT_PREFIX`, `SITE_URL`, `SITE_BASE`, `WARMUP_TOKEN` | переменные окружения сайта на хостинге |
| FTP-хост, логин, пароль (только прод) | GitHub Secrets |
| `WARMUP_TOKEN` для вызова прогрева из CI | GitHub Secrets (то же значение, что на хостинге) |
| `SITE_URL` для сборки данных в CI | GitHub Variables (домен не является секретом) |
| Локальные значения | `.env` (в `.gitignore`), в репозиторий не попадает |

Домена в коде нет: это стартер. Адрес берётся из аргумента `--site-url`, переменной `SITE_URL` или
остаётся `localhost`. Как PHP на FastVPS читает окружение, проверяется на сервере до написания кода.

## 8. Ветки и деплой

Порядок работы (ветки, PR, стенды, мерж, команды) — в `AGENTS.md`, здесь не дублируется.
Требования к процессу, а не к агенту:

- Прод обновляется только через workflow по `push` в главную ветку (default branch). Ручная заливка
  по FTP и прямой push исключены. Мерж = выкладка.
- Прод не обновляется со смерженного PR: payload такого события пустой.
- Главная ветка защищена: мерж только после одобрения заказчика.
- Стенд — статика в ветке `gh-pages` на GitHub Pages, папка `pr-<номер>`: выборка страниц, собранная
  `build.php`, с абсолютными ссылками на префикс стенда. Прод — FastVPS по FTP.
- Инкрементальная заливка FTP выполняется сторонним action: свой state-файл не пишем.
- Кэш на прод не заливается: он собирается на сервере при первом запросе и прогревается после деплоя.

## 9. Готовность PR

PR готов, когда:

- `Preview` зелёный, стенд открывается по ссылке из комментария, CSS и JS подхватились;
- `php -l` проходит, `php scripts/split-data.php` не выдаёт ошибок;
- у страниц стенда есть `title`, `h1` и абсолютный `canonical` (это проверяет `check.php`);
- форма отправляется локально (`php -S`) или на проде и письмо приходит; на стенде форма отключена;
- в описании PR есть что проверять.

## 10. Открытые вопросы

1. Назначение сайта и страницы — описывает заказчик при первом запросе.
2. Версия PHP на FastVPS.
3. Защита от спама: honeypot, капча или ничего.
4. Дизайн: макеты или на усмотрение Codex.
5. Доступ к стенду: публичный или закрытый (`noindex`). Сейчас стенд всегда закрыт от индексации.

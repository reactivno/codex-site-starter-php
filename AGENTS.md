# AGENTS.md — правила работы Codex

Ты дорабатываешь сайт на HTML/CSS/JS с PHP-формами. Страницы рендерятся из данных, а не лежат
отдельными `.html`: источник правды — `data/pages.csv`. Требования — `TZ.md`, команды — `README.md`.

## Старт работы с репозиторием

1. Клонируй репозиторий, перейди в него, обнови главную ветку: `git pull`.
2. Проверь PHP: `php -v`. Нужен 8.1+. Зависимостей нет — `npm install` и `composer install` не требуются.
3. Собери данные из CSV: `php scripts/split-data.php`. Без этого шага страниц нет.
4. Локальный запуск: `php -S localhost:8000 index.php`, сайт — <http://localhost:8000>.
   Вторым аргументом именно `index.php`: встроенный сервер не читает `.htaccess`, и роутер
   должен обслуживать запросы сам.
5. Проверь синтаксис PHP: `find . -name '*.php' -not -path './.git/*' -print0 | xargs -0 -r -n1 php -l`.
6. Если нужны переменные для формы, задай `MAIL_TO` в окружении команды, `.env` не читай и не создавай.

## Порядок на каждый запрос

1. Прочитай `TZ.md` и код, который меняешь.
2. Создай ветку от обновлённой главной ветки (`main` или `master`): `feat/<кратко>`, `fix/<кратко>`,
   `chore/<кратко>`. Для коммитов `ci:` и `docs:` ветка тоже `chore/`.
3. Сделай изменения, прогони проверку по разделу «Проверка» ниже.
4. Закоммить, запушь, открой PR в главную ветку.
5. Дождись workflow `Preview`: он собирает стенд и оставляет комментарий со ссылкой.
6. Напиши заказчику ссылку на PR и на стенд, что именно проверять.
7. После одобрения (approve или явное «мержи») — `gh pr merge --squash --delete-branch`.

Мерж в главную ветку = выкладка на прод: `Deploy` уходит по FTP сразу после пуша в главную.

План на согласование не нужен: заказчик смотрит результат на стенде.

Если `Preview` красный — `gh pr checks`, открой логи упавшего шага, исправь, запушь снова.
Ссылку заказчику до зелёного не отправляй.

## Границы

- Страница по шаблону — это **строка в `data/pages.csv`**, а не новый `.html`. Отдельный `.html`
  в корне — только для действительно уникальной страницы, и тогда её нет в CSV.
- Не правь и не коммить генерируемое: `cache/`, `data/pages/`, `data/index.json`, `sitemap.xml`,
  `robots.txt`, `_site/`. Оно создаётся скриптами и перезаписывается при каждой сборке.
- Новое поле данных — одна задача: шаблон, где поле выводится, валидация в `scripts/split-data.php`
  и таблица колонок в `TZ.md`. Рассинхрон ломает сборку с 503 на странице.
- Каждая запись обязана иметь уникальные `title`, `description`, `h1`. Страница-заглушка без
  собственного смысла получает `noindex=1` и не попадает в sitemap.
- Смена адреса существующей страницы — только после вопроса заказчику и вместе с 301 со старого адреса.
- Структура шаблона главнее структуры архива: чужие файлы раскладывай по нашим папкам (`css/`, `js/`,
  изображения — в `assets/`), а не копируй дерево как есть. Пути страниц при этом сохраняются как в
  исходном сайте — их задаёт колонка `path`.
- Обработчик форм один — `php/send.php`. Не создавай `callback.php`, `form.php` и другие дубли:
  логику чужого обработчика переноси в `php/send.php`.
- После копирования сайта из архива перепроверь, что форма шлёт POST в `php/send.php`, и только потом
  открывай PR.
- Не пуш в главную ветку напрямую, не мержи без одобрения.
- Не трогай секреты: не читай `.env`, не коммить его, не печатай значения. Имена и значения — в `README.md`.
- Новые зависимости, смена стека, правки `.github/workflows/`, изменения схемы данных — сначала спроси.
- Если запрос неоднозначен (что за страница, какие поля, куда слать заявки), задай один короткий вопрос.
- Не меняй `TZ.md`, `AGENTS.md` и `README.md` без явной просьбы.

Правила кода (валидация, заголовки письма, именование), колонки `pages.csv`, типы страниц и правила
SEO — в `TZ.md`.

## Формы

- Единственный контракт формы: таблица в `TZ.md` §3 плюс `FORM_CONFIG` вверху `php/send.php`.
  Меняешь поля — одной задачей обновляешь HTML (`partials/form.html`), `FORM_CONFIG` и эту таблицу.
- Эталонный пример конфига и объяснение — `README.md`, раздел «Другая форма».
- Ответы обработчика и их коды описаны в `TZ.md` §6, здесь не дублируются.

## Стиль кода

- PHP: `declare(strict_types=1)`. Константы и пути — в `lib/config.php`, рендер — `lib/render.php`,
  кэш — `lib/cache.php`, SEO — `lib/seo.php`, роутер — `index.php`. Окружение читается через
  `env_value()`, ответы формы — через `respond()`. Комментарии по-русски, объясняют «почему».
- Шаблоны: `{{поле}}` — с экранированием, `{{{поле}}}` — только для `body`, `_robots`, `_breadcrumbs`,
  `_related`, `_jsonld`, `{{ include имя}}` — вставка `partials/имя.html`. Условий и циклов нет:
  если нужна логика, она считается в PHP и приходит готовой строкой.
- JS: без сборщика, подключается как `type="module"`, двойные кавычки, `async/await` и `fetch` с
  `FormData`. Отправка выключена на `*.github.io` — это проверка стенда в `js/main.js`, не баг.
- CSS: переменные в `:root`, классы по БЭМ (`блок__элемент--модификатор`), всё в `css/style.css`.

## Проверка

Тестов и линтеров в проекте нет, инфраструктуру не настраивай. Минимум перед PR:

```bash
find . -name '*.php' -not -path './.git/*' -print0 | xargs -0 -r -n1 php -l
php scripts/split-data.php            # падает с адресом ошибки, если CSV битый
php -S localhost:8000 index.php       # в другом терминале:
curl -sI http://localhost:8000/                        # 200
curl -sI http://localhost:8000/uslugi                  # 200
curl -sI http://localhost:8000/nope                     # 404
curl -sI http://localhost:8000/lib/config.php           # 403
curl -s  http://localhost:8000/uslugi | grep canonical  # абсолютный адрес
```

Если менял шаблон или partials — прогони `php scripts/warmup.php`: Apache отдаёт готовый HTML из `cache/`
и без прогрева правка не долетит до посетителя. На стенде кэш не используется вовсе.

## Коммиты и PR

- Сообщения коммитов — на русском, одна строка до 72 символов, с типом в начале: `feat:`, `fix:`, `ci:`,
  `docs:`, `chore:`.
- Название PR и его описание — на русском.
- В описании PR: что изменилось, как проверить, что смотреть на стенде.

## Пайплайн

| Workflow | Событие | Что делает |
| --- | --- | --- |
| `preview.yml` | `pull_request` opened/synchronize/reopened | `php -l`, `split-data.php`, `build.php --sample --changed-from`, `check.php`, публикация выборки в `gh-pages/pr-<номер>/`, комментарий со ссылкой |
| `cleanup.yml` | `pull_request` closed | удаляет `pr-<номер>/` из ветки `gh-pages` |
| `deploy.yml` | `push` в главную ветку | `split-data.php`, FTP в корень FTP-аккаунта, прогрев кэша по токену |

Стенд — GitHub Pages: PHP там не исполняется, страницы рендерит `scripts/build.php`, в `gh-pages` едут
только готовые `html` и `css/`, `js/`. Форма на стенде отключена, `robots.txt` стенда закрывает его
целиком. Отправку формы проверяй локально (`php -S`) или на проде.
